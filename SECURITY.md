
# Segurança

Não publicar vulnerabilidades, credenciais, tokens ou dados pessoais em issues públicas.

## Regras

- Nunca versionar segredos reais.
- Utilizar variáveis de ambiente ou secret managers.
- Remover dados sensíveis de logs e exemplos.
- Exigir confirmação antes de ações destrutivas ou alterações em produção.

Para reportar uma vulnerabilidade, contactar o responsável do projeto por um canal privado.
